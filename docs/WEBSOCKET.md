# Contrato de mensagens WebSocket

Este documento define o contrato do MVP entre o navegador e o servidor autoritativo em `ws/`. O transporte é WebSocket com mensagens JSON UTF-8, uma mensagem por frame. O servidor valida todas as intenções e é a única fonte de verdade para salas, posições, respostas, progresso e ranking.

## Envelope

Toda mensagem usa este formato:

```json
{
    "type": "rooms.list.request",
    "request_id": "id-unico-da-requisicao",
    "payload": {}
}
```

`type` identifica a mensagem. `payload` sempre é um objeto. Comandos que esperam uma resposta direta incluem `request_id`; a resposta ou erro correspondente repete esse valor. Mensagens assíncronas do servidor, como broadcasts, não precisam de `request_id`. IDs de usuário são UUIDs efêmeros gerados pelo cliente e nunca são persistidos.

O cliente envia intenções, nunca estado calculado: não envia posição absoluta, pontuação, ranking, owner ou resultado correto. Campos desconhecidos, tipos inválidos e comandos fora de estado são rejeitados com `error`.

## Cliente para servidor

| `type`               | `payload`                                                                                                                     | Uso                                                                                                                                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session.hello`      | `{ "protocol_version": 1, "user_id": "uuid", "nickname": "Ana", "character_id": "character-id" }`                             | Primeiro comando após abrir a conexão. Registra a identidade efêmera ou retoma a sessão interrompida com o mesmo UUID dentro da tolerância de 30 segundos.                                                  |
| `rooms.list.request` | `{}`                                                                                                                          | Busca a lista atual de salas disponíveis. Deve ser enviado ao entrar na Home, pelo botão de atualizar e pelo polling descrito abaixo.                                                                       |
| `room.create`        | `{ "name": "Sala", "mode": "classic", "floors": 10, "notebooks_per_floor": 3, "time_limit_seconds": null, "max_players": 6 }` | Cria uma sala e coloca o criador como owner e primeiro jogador. O owner é o usuário da sessão, não um campo fornecido no payload. Requer `request_id`.                                                      |
| `room.join`          | `{ "room_id": "uuid-da-sala" }`                                                                                               | Entra na sala como jogador. Não aceita papel de espectador.                                                                                                                                                 |
| `room.leave`         | `{}`                                                                                                                          | Sai da sala atual.                                                                                                                                                                                          |
| `room.configure`     | `{ "name": "Sala", "mode": "classic", "floors": 10, "notebooks_per_floor": 3, "time_limit_seconds": null, "max_players": 6 }` | Atualiza os campos enviados da configuração. Somente o owner pode alterar configurações e o servidor valida os limites documentados em `RULES.md`.                                                          |
| `match.start`        | `{}`                                                                                                                          | Solicita início da partida. Somente o owner pode iniciar.                                                                                                                                                   |
| `player.move`        | `{ "sequence": 42, "direction": "northeast" }`                                                                                | Envia intenção de movimento. `direction` é `north`, `northeast`, `east`, `southeast`, `south`, `southwest`, `west`, `northwest` ou `stop`. A sequência cresce por jogador; o cliente não envia coordenadas. |
| `question.answer`    | `{ "question_id": 17, "option_index": 1 }`                                                                                    | Envia a alternativa da questão de qualquer caderno ainda disponível no andar. O índice começa em zero; requer `request_id`.                                                                                 |
| `spectator.follow`   | `{ "target_user_id": "uuid-do-jogador-ativo" }`                                                                               | Espectador eliminado ou que concluiu a run seleciona um jogador ativo cujo campo de visão deseja acompanhar.                                                                                                |

`room.join`, `room.leave`, `spectator.follow` e `question.answer` exigem `request_id`. Repetir `room.join` na mesma sala retorna o snapshot atual sem duplicar o participante; entrar em uma segunda sala sem sair da primeira é rejeitado. `room.join` não aceita um campo de papel: não existe entrada externa como espectador. `spectator.follow` só pode ser usado por participante que já concluiu a run ou foi eliminado no mata-mata, e seu alvo deve ser outro jogador ativo da mesma sala. Ao sair, o owner é transferido para o membro restante presente há mais tempo; se não houver outros membros, a sala é removida do SQLite e da presença em memória, sem snapshot posterior.

`room.configure` pode conter somente `name`, `mode`, `floors`, `notebooks_per_floor`, `time_limit_seconds` e `max_players`; campos omitidos permanecem inalterados. Somente o owner pode configurar uma sala `waiting`, e o novo limite de jogadores não pode ficar abaixo da quantidade atual de participantes. `time_limit_seconds: null` significa tempo ilimitado. `match.start` também é exclusivo do owner e só inicia uma sala `waiting` com pelo menos dois jogadores; caso contrário, retorna `INSUFFICIENT_PLAYERS`. Antes de iniciar, o servidor exige questões distintas suficientes para todos os espaços da partida conforme `RULES.md`. Todos entram na sala como jogadores; eliminacao no mata-mata ou conclusao de run os converte em espectadores. Espectadores nao podem movimentar personagens nem responder questoes, e recebem somente os dados do jogador ativo que acompanham.

Ao aceitar `match.start`, o servidor sorteia questões distintas para todos os slots de andar/caderno e cria uma permutação de ordem e rótulos de caderno para cada participante. Essa distribuição, incluindo as respostas corretas, existe somente na memória do servidor e não é enviada no `room.snapshot` nem junto de `match.started`. No modo clássico, o servidor envia `question.presented` para cada caderno disponível do andar, simultaneamente; o jogador pode escolher qualquer um. Uma resposta errada bloqueia apenas o caderno respondido. Uma resposta correta bloqueia os demais cadernos e abre a porta. Se todos os cadernos forem respondidos incorretamente, respostas ficam bloqueadas por 5 segundos; depois, a porta abre e o jogador precisa atravessá-la. Ao avançar, o jogador surge no tile zero-based `[14][7]`, e a porta do novo andar começa fechada. Jogadores ativos só recebem avatares e movimentos de participantes que estejam no mesmo andar; quando alguém muda de andar, snapshots atualizam os conjuntos visíveis para remover e adicionar os avatares necessários. Cada jogador começa na posição lógica `(50, 50)`, dentro do mapa `x`/`y` de `0` a `100`, inclusive. Um movimento cardinal percorre uma unidade; diagonais são normalizadas para também percorrer uma unidade total. Posições além dos limites são truncadas à borda pelo servidor.

Ao cruzar a porta do último andar em qualquer modo, o jogador conclui a run e vira espectador. No mata-mata, cada jogador recebe uma pergunta por andar; uma resposta errada elimina imediatamente o participante e inicia o modo espectador. Quem conclui acompanha outro jogador ativo, mas não pode mover-se nem responder. Os demais continuam jogando. Quando não há competidores ativos, vence o primeiro a concluir uma run (`questions_exhausted`); sem conclusão, a partida termina por último jogador ativo/desconectado ou sem vencedor, conforme `RULES.md`. O prazo de reconexão após desconexão continua sendo 30 segundos. O encerramento impede novas respostas e movimentos e retorna a sala ao lobby.

O cronômetro inicia no servidor ao aceitar `match.start`. Se `time_limit_seconds` for `null`, nenhum timeout é agendado; caso contrário, o deadline é o instante de início mais esse limite. Respostas e movimentos só são aplicados quando `now < deadline`; exatamente no deadline, o timeout encerra a partida antes da ação. `match.ended` usa `reason: "time_limit_reached"` no timeout, `reason: "all_players_finished"` quando todos concluem no clássico e, no mata-mata, `reason: "questions_exhausted"` quando nao restam competidores ativos e alguem concluiu a run. O resultado prevalece de forma determinística sobre uma última resposta processada no deadline.

## Servidor para cliente

| `session.ready`       | `{ "protocol_version": 1, "user_id": "uuid" }`                                                                                                                                                                                                                                                                                     | Resposta a `session.hello`; a sessão pode então enviar os demais comandos.                                                                                                                                                                                                                                                                                                         |
| `rooms.list`          | `{ "rooms": [{ "room_id": "uuid", "name": "Sala", "mode": "classic", "floors": 10, "notebooks_per_floor": 3, "time_limit_seconds": null, "max_players": 6, "player_count": 2, "status": "waiting" }] }`                                                                                                                            | Resposta a cada `rooms.list.request`, somente para quem pediu. Lista somente salas `waiting`; `player_count` conta a presença reservada durante a tolerância de reconexão. Não há broadcast da lista.                                                                                                                                                                              |

| `room.left`           | `{ "room_id": "uuid" }`                                                                                                                                                                                                                                                                                                            | Confirma a saída ao usuário que saiu. Os demais recebem o `room.snapshot` atualizado imediatamente.                                                                                                                                                                                                                                                                                |
| `match.started`       | `{ "room_id": "uuid" }`                                                                                                                                                                                                                                                                                                            | Confirma início aos participantes; cada jogador ativo recebe sua primeira `question.presented`. Uma partida de mata-mata com um participante termina imediatamente.                                                                                                                                                                                                                |
| `match.snapshot`      | `{ "revision": 1, "viewer": { "status": "playing", "target_user_id": null }, "players": [{ "user_id": "uuid", "nickname": "Ana", "character_id": "bobabao", "x": 0, "y": 0, "direction": "stop", "floor": 1, "door_open": false, "answered_notebooks": [], "status": "playing" }] }`                                               | Snapshot inicial/ressincronização. | `player.eliminated`   | `{ "user_id": "uuid", "reason": "wrong_answer" }`                                                                                                                                                                                                                                                                                  | Broadcast aos jogadores ativos para remover imediatamente o avatar do eliminado. O próprio eliminado recebe `spectator.started`. Motivos incluem resposta incorreta ou expiração da reconexão.                                                                                                                                                                                     |
| `spectator.started`   | `{ "user_id": "uuid", "target_user_id": "uuid-do-jogador-ativo", "reason": "run_finished" }`                                                                                                                                                                                                                                       | Informa que o jogador foi eliminado (`wrong_answer`, `reconnect_expired`) ou concluiu a run (`run_finished`) e passou a espectador; o alvo pode ser `null` se nenhum competidor ativo restar.                                                                                                                                                                                      |
| `spectator.following` | `{ "target_user_id": "uuid-do-jogador-ativo" }`                                                                                                                                                                                                                                                                                    | Confirma a troca do jogador acompanhado; o alvo pode ser `null` quando o alvo anterior deixa de estar ativo e não resta outro jogador.                                                                                                                                                                                                                                             |
| `question.presented`  | `{ "question_id": 17, "floor": 1, "notebook_id": "id-do-caderno", "notebook_label": 2, "notebook_position": { "row": 3, "column": 2 }, "prompt": "Enunciado", "options": ["Opção A", "Opção B"] }`                                                                                                                                 | Uma apresentação por caderno disponível, enviada somente ao jogador correspondente no início e ao entrar em cada andar; não é enviada novamente ao errar. `notebook_position` identifica o tile do mapa (índices iniciados em zero). | `ranking.updated`     | `{ "revision": 19, "entries": [{ "rank": 1, "user_id": "uuid", "nickname": "Ana", "floor": 4, "status": "playing" }] }`                                                                                                                                                                                                            | Snapshot ordenado enviado no início e após mudanças de progresso, eliminação, conclusão de run, participantes ou término. | `match.ended`         | `{ "reason": "time_limit_reached", "entries": [{ "rank": 1, "user_id": "uuid", "nickname": "Ana", "floor": 3, "status": "playing" }] }`                                                                                                                                                                                            | Enviado a todos os participantes conectados no encerramento; em seguida, a sala retorna a `waiting` e todos recebem `room.snapshot`. O cliente mostra motivo e ranking em um popup, retém esse snapshot até confirmação ou fechamento automático após 8 segundos e então retorna ao lobby. A presença e a distribuição transitória são limpas; o owner pode iniciar outra partida. |
| `error`               | `{ "code": "ROOM_FULL", "message": "A sala está cheia.", "retryable": false }`                                                                                                                                                                                                                                                     | Erro de comando. No jogo, todos os cadernos disponíveis podem ser acessados ao se aproximar de seus respectivos tiles `notebook_position`. A tecla `E` abre o painel do caderno próximo; as setas navegam pelas alternativas e pela opção `[X]`, `E` confirma e `Esc` fecha. O painel fica centralizado e limitado a 98% da área do canvas, e usa a fonte pixelada da interface. Cadernos respondidos incorretamente ficam bloqueados; um acerto abre a porta e bloqueia os demais. O cliente envia somente `question_id` e o índice escolhido em `question.answer`; o enunciado, as alternativas e o resultado permanecem no canvas, sem depender de mouse ou DOM.

O servidor envia `session.ready` após receber uma identidade válida. `room.create` retorna `room.snapshot` com o criador como owner e primeiro participante; `room.join` retorna o snapshot ao participante e o transmite imediatamente aos membros conectados existentes. `room.leave` retorna `room.left` ao solicitante e transmite o snapshot atualizado aos membros restantes. Se o owner sair, o snapshot informa o novo owner; se a sala ficar vazia, ela é removida e não há snapshot para os antigos participantes. Cada participante inclui `connected`; `revision` aumenta em mudanças de membro/conexão e permite detectar estado antigo após reconexão ou processamento assíncrono. No snapshot da sala, `role` é sempre `player`; eliminação e modo espectador são estados da partida, não papéis de entrada. Na partida, `player.eliminated` remove o avatar dos jogadores ativos, enquanto o eliminado permanece como membro e recebe `spectator.started`; quem termina a run recebe o mesmo evento com `reason: "run_finished"`. `spectator.follow` retorna `spectator.following` apenas ao solicitante e envia um novo `match.snapshot` com o alvo escolhido. Quando o alvo acompanhado e eliminado ou conclui a run, o servidor redireciona automaticamente seus espectadores para outro jogador ativo, confirma a mudança com `spectator.following` e atualiza o snapshot. Atualizações de jogo devem ser enviadas apenas ao jogador ativo e a seus espectadores, nunca aos demais membros. A sequência WebSocket preserva a ordem das mensagens.

## Sincronização e salas

Configuração, owner, conexão e quantidade/identidade de participantes são estado da sala e geram `room.snapshot` imediatamente para todos os membros conectados. Entrada/saída atualiza o snapshot dos participantes; movimentos aceitos geram `player.moved` imediatamente e mudanças na classificação geram `ranking.updated` imediatamente para jogadores ativos e eliminados. A sequência de movimento deve ser um inteiro seguro não negativo e maior que a última sequência aceita daquele jogador; coordenadas enviadas pelo cliente são rejeitadas. Jogadores ativos recebem os movimentos de todos os jogadores ativos. Espectadores não podem enviar movimento e só recebem atualizações visíveis no campo de visão acompanhado; `match.snapshot` não deve revelar posições fora dele.

O ranking é sempre calculado pelo servidor; mensagens de ranking do cliente não são comandos válidos e pontuação/colocação não são aceitas como entrada. Em ambos os modos, maior andar fica à frente; no mesmo andar, vale a ordem de chegada registrada pelo servidor, com a ordem de entrada como desempate final. O estado jogando/eliminado/concluído é informativo e não altera essa ordem. A revisão começa em `1` no início da partida e aumenta a cada snapshot de ranking.

A lista de salas é uma consulta, não um fluxo em tempo real: solicitar ao abrir a Home, ao acionar atualizar e a cada 15 segundos enquanto a Home estiver visível. Interromper o polling ao sair da tela e fazer uma nova consulta ao reconectar. A lista inclui apenas os dados resumidos necessários para descoberta; entrar na sala sempre exige nova validação do servidor. O MVP usa WS para essa consulta e não cria uma API HTTP.

## Erros

`error.payload.code` usa um código estável para lógica do cliente; `message` é texto para apresentação e não deve ser interpretado. `retryable` indica se faz sentido repetir a mesma ação sem alterar seus dados.

| Código                   | Significado                                                 |
| ------------------------ | ----------------------------------------------------------- |
| `INVALID_MESSAGE`        | JSON, envelope, tipo ou payload inválido.                   |
| `SESSION_REQUIRED`       | A sessão ainda não enviou `session.hello`.                  |
| `ROOM_NOT_FOUND`         | Sala inexistente ou já removida.                            |
| `ROOM_FULL`              | Limite de jogadores atingido.                               |
| `ROOM_IN_PROGRESS`       | A ação exige uma sala aguardando.                           |
| `INVALID_ROOM_SETTINGS`  | Configuração fora dos limites permitidos.                   |
| `NOT_ROOM_OWNER`         | Ação de owner enviada por outro participante.               |
| `NOT_IN_ROOM`            | Ação requer participação na sala.                           |
| `FORBIDDEN_ROLE`         | Ação de jogo enviada por espectador.                        |
| `INVALID_ANSWER`         | Pergunta, alternativa ou estado da resposta inválido.       |
| `INSUFFICIENT_QUESTIONS` | Catálogo sem questões distintas suficientes para a partida. |
| `INSUFFICIENT_PLAYERS`   | Menos de dois jogadores na sala para iniciar a partida.     |
| `STALE_INPUT`            | Sequência de movimento antiga ou repetida.                  |
| `ACTION_NOT_ALLOWED`     | Ação incompatível com o estado atual da sala/partida.       |
| `INTERNAL_ERROR`         | Falha inesperada; não expõe detalhes internos.              |

## Transições de tela

| Tela atual    | Evento/ação                                                    | Próxima tela                                                      |
| ------------- | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| Perfil        | Conexão aberta e `session.ready`                               | Home; solicita `rooms.list.request`.                              |
| Home          | `room.create` ou `room.join` aceito e `room.snapshot` recebido | Sala. Um erro mantém na Home e é apresentado ao usuário.          |
| Sala          | `room.snapshot`                                                | Atualiza configuração e participantes sem trocar de tela.         |
| Sala          | `match.started` e `match.snapshot`                             | Jogo.                                                             |
| Jogo          | `question.presented`, `player.moved` ou `ranking.updated`      | Atualiza a partida atual sem trocar de tela.                      |
| Jogo          | `match.ended`                                                  | Resultado.                                                        |
| Resultado     | Snapshot da sala após conclusão/retorno                        | Sala, pronta para outra partida.                                  |
| Qualquer tela | `error`                                                        | Permanece na tela; mostra o erro sem aplicar a mutação rejeitada. |

Os motivos aceitos em `match.ended` são `time_limit_reached`, `all_players_finished`, `last_player_standing`, `questions_exhausted`, `no_players_remaining` e `last_player_disconnected`. Cada entrada do ranking contém `rank`, `user_id`, `nickname`, `floor` e `status` (`playing`, `eliminated` ou `finished`).

As regras de tolerância de desconexão, reconexão, espectadores e desempate estão em `RULES.md`. Uma reconexão com o mesmo UUID dentro dos 30 segundos retoma a participação e recebe snapshots atuais, além da pergunta pendente se ainda houver uma; depois desse prazo, aplica-se a saída ou eliminação definida para o modo. No lobby e no clássico, a expiração remove o membro e transfere o ownership ao participante conectado há mais tempo; em mata-mata durante a partida, transfere o ownership sem remover a participação, para que o fluxo de espectador seja aplicado. Se a remoção deixar a sala vazia, o servidor apaga a sala do SQLite e da presença em memória. Se a última tolerância do mata-mata expirar sem outro competidor ativo nem uma run concluída, `match.ended` usa `reason: "last_player_disconnected"` e declara vencedor o jogador que acabou de expirar.
